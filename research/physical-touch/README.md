# Проверка тачей на физическом устройстве Aurora

7 октября 2026 года проверено устройство `defaultuser@192.168.2.44`, Aurora 5.2.0.259, aarch64. Ввод через uinput работает: подтверждены точные tap и системный свайп. Использован уже установленный `ru.kotdath.AudbBridge` в режиме `--bridge-helper`. На момент этой проверки новая служба audb ещё не была реализована. Сейчас используется `audb-agent`; старое приложение удалено из актуального дерева. Рабочий сценарий описан в [README](../../README.md#physical-touchscreen).

UI дерево отложено. Проверка выполнялась через команды ввода и скриншоты, без использования дерева элементов.

## Характеристики устройства

| Параметр | Наблюдение |
| --- | --- |
| Физический touchscreen | `himax-touchscreen`, в этой конфигурации `/dev/input/event5` |
| Права evdev | `root:input`, `0660`; defaultuser входит в input |
| Доступ uinput | `/dev/uinput`, `root:root`, `0600` |
| Протокол | Multitouch со слотами, slot 0…9, tracking ID 0…65535 |
| Оси физического touchscreen | X 0…1999, Y 0…1199 |
| Размер панели из DRM modes | 1200×2000 |
| Текущий скриншот | 2000×1200 |
| Рабочая конфигурация виртуального touchscreen | X 0…1199, Y 0…1999, Qt orientation 2 |

Диапазоны физических осей получены из `libinput record /dev/input/event5`; свойства panel modes — из `/sys/class/drm/card*-*/modes`. Команда `libinput list-devices` распознаёт физическое устройство как touch. Номер event5 не является постоянным API и должен определяться при подключении.

## Результаты действий

| Действие | Backend | Результат |
| --- | --- | --- |
| Swipe от края | uinput через установленный helper | Flutter приложение ушло на домашний экран |
| Tap по карточке справки | evdev через helper от defaultuser | Открылась справка; root не потребовался |
| Tap с размерами виртуального устройства 2000×1200 без поворота | uinput | Касания попадали в другое место либо в пустую область |
| Tap по возврату из раздела справки | uinput, панель 1200×2000 и orientation 2 | Вернулся главный экран справки |
| Tap по пункту Жесты в приложениях | Та же конфигурация uinput | Открылся именно выбранный раздел |
| Swipe внутри раздела справки | uinput через helper | Вместо ожидаемого возврата к списку активным стало Flutter приложение; надёжность этого сценария не подтверждена |

Последний переход требует отдельной проверки. Пересоздание виртуального устройства каждым вызовом helper, особенности маршрутизации жеста и возможное параллельное управление экраном являются гипотезами, а не установленной причиной. Системный swipe и точные tap подтверждены визуально; по exit code отдельно нельзя судить о результате в интерфейсе.

## Текущий интерфейс audb

Для повторной проверки используйте установленный `audb-agent` и зарегистрированное устройство. Координаты относятся к актуальному PNG; перед действием нужно проверить скриншот и ориентацию.

```bash
audb --device phone screenshot --output ./before.png
audb --device phone --json tap 900 323 --duration 80
audb --device phone --json swipe edge-up --duration 400
audb --device phone screenshot --output ./after.png
```

Координаты tap приведены как пример из первоначального исследования, а не универсальная цель для любого экрана. Служба определяет геометрию и преобразует координаты; параметры старого helper ей передавать не нужно.

В первоначальной проверке виртуальный и физический backend использовали разные системы координат. Для uinput с осями X 0…1199, Y 0…1999 и orientation 2 экранные координаты 900,323 преобразовывались в сырые 876,900. Копировать диапазоны физического evdev в создаваемый uinput и считать их координатами PNG нельзя. Остальные повороты требуют отдельной проверки.

## Прототип постоянного устройства

[uinput_probe.c](uinput_probe.c) — отдельный исследовательский процесс, который создаёт виртуальный touchscreen один раз, принимает команды tap и swipe через stdin, отпускает контакт и уничтожает устройство при завершении. Он не входит в рабочий audb и не объявлен проверенным backend.

Исходник успешно собран GCC в target `AuroraOS-5.2.1.200-aarch64` с `-std=c11 -O2 -Wall -Wextra -Werror`. SDK headers не содержат новых `UI_DEV_SETUP` и `UI_ABS_SETUP`, поэтому прототип использует существующий `uinput_user_dev` интерфейс, как старый helper.

Пример сборки из репозитория audb, внутри настроенного SDK:

```bash
sb2 -t AuroraOS-5.2.1.200-aarch64 -m sdk-build gcc \
  -std=c11 -O2 -Wall -Wextra -Werror \
  research/physical-touch/uinput_probe.c -o target/audb-uinput-probe
```

Новый ELF на устройстве не запустился ни от defaultuser, ни через devel-su. Для `/home` дополнительно действует mount option `noexec`. В `/tmp` журнал подтвердил другую причину отказа:

```text
op=appraise_data cause=IMA-signature-required
name="/tmp/audb-uinput-probe-20261007"
```

Постоянный прототип требуется упаковать, подписать и установить, затем проверить фактический запуск с учётом IMA. Проверка подписи RPM при установке и подписи исполняемого файла при запуске — разные условия. Пока готовность постоянного input процесса не подтверждена.

Временные бинарники и изображения на устройстве после проверки удалены. В `/proc/bus/input/devices` не осталось виртуальных устройств audb. Полная служба и пакеты не устанавливались; исходный Flutter экран снова активен.

## Решение для адаптации audb

Основной кандидат — постоянный виртуальный touchscreen внутри службы. Исследование подтверждает возможность доставки тачей в интерфейс через uinput. Резервный evdev backend также практически пригоден для tap, но зависит от прав пользователя и состояния реального touchscreen.

Для реализации нужны:

1. Подписанный минимальный пакет прототипа и подтверждённый запуск.
2. Отдельная модель геометрии PNG, панели и input backend с ориентацией из compositor или пользовательской графической сессии. Размер PNG сам по себе не различает повороты 90 и 270 градусов.
3. Постоянный fd виртуального устройства и проверка готовности после регистрации.
4. Проверки обычной прокрутки, long press, double tap и серии действий на одном fd.
5. Проверки отмены, отключения клиента и перезапуска службы с отпусканием всех контактов.
6. Проверки остальных ориентаций и другого физического устройства перед объявлением общего паритета.

Исходная реализация событий удалённого прототипа сохранена в [истории Git](https://github.com/KotDath/audb/blob/190bbaa/app/AudbBridge/src/helpercli.cpp). Текущая реализация: [audb-agent](../../audb-agent/src/lib.rs). Требования к интерфейсу и этапам: [план адаптации](../../PLAN_DEVICE_SUPPORT.md).
